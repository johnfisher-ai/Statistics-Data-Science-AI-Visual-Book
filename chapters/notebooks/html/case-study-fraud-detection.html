Case Study: Fraud Detection

Library-first with scikit-learn and imbalanced-learn, and heavily visual.
Statistics, Data Science and AI: A Visual Handbook · John Fisher · 2026

Fraud detection finds a needle in a haystack¶

Fraud is rare, here about 1 in 25 transactions, and that rarity breaks the usual playbook. A model that flags nothing is already 96% accurate, so accuracy is a trap. This case study uses scikit-learn and imbalanced-learn to apply the tools that actually work on imbalanced data: the right metrics (precision, recall, PR-AUC), ways to rebalance the learning (class weights, SMOTE), and tuning the decision threshold to the real cost of a missed fraud versus a false alarm.

STEP 1 · DEFINE THE OBJECTIVE
Catch fraud at low cost
The two errors do not cost the same.

The goal. Flag fraudulent card transactions in real time so they can be blocked or reviewed. The costs are wildly asymmetric. A missed fraud (false negative) can cost the full transaction amount plus chargeback fees and lost trust, while a false alarm (false positive) costs only a few minutes of an analyst's time or a declined-card annoyance. That imbalance in cost, on top of the imbalance in the data, is the whole story.

The defining feature of this dataset. Only about 4% of transactions are fraud. That imbalance is the problem, so it has to be handled head-on instead of smoothed away. It means (1) accuracy will be useless, (2) a model will be tempted to ignore the minority class entirely, and (3) we have very few fraud examples to learn from. Everything below is a response to those three facts. There is also routine mess to clean in the form of duplicates, negative amounts, and merchant labels in mixed case.

STEP 6 · TRANSFORM + SPLIT
A pipeline and a stratified split
With rare classes, stratify so both sets keep the same fraud rate.
In [7]:
numeric = ['amount','hour','txns_last_hour','foreign_transaction','card_present','account_age_days','distance_from_home_km']
categorical = ['merchant_category']
preprocess = ColumnTransformer([
    ('num', Pipeline([('impute', SimpleImputer(strategy='median')), ('scale', StandardScaler())]), numeric),
    ('cat', OneHotEncoder(handle_unknown='ignore'), categorical)])
X = df[numeric + categorical]; y = df['is_fraud']
X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.25, random_state=0, stratify=y)
print('train:', X_train.shape[0], 'txns,', y_train.sum(), 'fraud | test:', X_test.shape[0], 'txns,', y_test.sum(), 'fraud')

train: 6741 txns, 264 fraud | test: 2247 txns, 88 fraud

Stratify is not optional here. With only about 4% fraud, an ordinary random split could hand the test set a wildly different fraud rate by chance, or too few fraud cases to measure anything. stratify=y forces both train and test to keep the same 4% fraud rate. Preprocessing lives in a pipeline, as always, so imputation and scaling never leak across the split.

STEP 7 · THE ACCURACY TRAP
Why the obvious metric lies
A do-nothing model looks excellent.
In [8]:
baseline = DummyClassifier(strategy='most_frequent').fit(X_train, y_train)
bp = baseline.predict(X_test)
print('BASELINE (flag nothing): accuracy = %.3f  but recall = %.3f  -> catches ZERO fraud' % (accuracy_score(y_test,bp), recall_score(y_test,bp)))
plain = Pipeline([('prep', preprocess), ('clf', LogisticRegression(max_iter=3000))]).fit(X_train, y_train)
pp = plain.predict(X_test)
print('PLAIN logistic:          accuracy = %.3f  recall = %.3f  precision = %.3f' % (accuracy_score(y_test,pp), recall_score(y_test,pp), precision_score(y_test,pp)))
print('  -> 96%% accurate, yet it still misses about 85%% of fraud!')

BASELINE (flag nothing): accuracy = 0.961  but recall = 0.000  -> catches ZERO fraud

PLAIN logistic:          accuracy = 0.964  recall = 0.148  precision = 0.684
  -> 96%% accurate, yet it still misses about 85%% of fraud!

Accuracy is worthless on imbalanced data. A model that predicts 'legit' for every transaction scores 96% accuracy and catches not a single fraud. Even a real logistic regression, trained normally, inherits the bias. It hits 96% accuracy but a recall of only about 0.15, missing most fraud, because the loss function is dominated by the 96% majority. So judge a fraud model by recall (what fraction of fraud did we catch?) and precision (of the alerts we raised, how many were real?) instead of accuracy.

STEP 8 · HANDLE THE IMBALANCE
Two ways to make the model care
Reweight the classes, or resample the data.
In [9]:
results = {}
def evaluate(name, model):
    model.fit(X_train, y_train); pred = model.predict(X_test); prob = model.predict_proba(X_test)[:,1]
    results[name] = dict(acc=accuracy_score(y_test,pred), recall=recall_score(y_test,pred), precision=precision_score(y_test,pred),
        f1=f1_score(y_test,pred), roc=roc_auc_score(y_test,prob), prauc=average_precision_score(y_test,prob), prob=prob)
    r=results[name]; print(f'{name:16s} acc {r["acc"]:.3f} | recall {r["recall"]:.3f} | precision {r["precision"]:.3f} | ROC-AUC {r["roc"]:.3f} | PR-AUC {r["prauc"]:.3f}')
evaluate('plain', Pipeline([('prep', preprocess), ('clf', LogisticRegression(max_iter=3000))]))
evaluate('class_weight', Pipeline([('prep', preprocess), ('clf', LogisticRegression(max_iter=3000, class_weight='balanced'))]))
evaluate('SMOTE', ImbPipeline([('prep', preprocess), ('smote', SMOTE(random_state=0)), ('clf', LogisticRegression(max_iter=3000))]))
fig, ax = plt.subplots(figsize=(8.4,4.4))
names=list(results); x=np.arange(len(names)); w=0.38
ax.bar(x-w/2, [results[n]['acc'] for n in names], w, label='accuracy', color=GREY)
ax.bar(x+w/2, [results[n]['recall'] for n in names], w, label='recall (fraud caught)', color=EM)
ax.set_xticks(x); ax.set_xticklabels(names); ax.set(ylabel='score', title='Accuracy barely moves; recall is transformed'); ax.legend()
plt.tight_layout(); plt.show()

plain            acc 0.964 | recall 0.148 | precision 0.684 | ROC-AUC 0.889 | PR-AUC 0.364
class_weight     acc 0.800 | recall 0.784 | precision 0.138 | ROC-AUC 0.889 | PR-AUC 0.355
SMOTE            acc 0.807 | recall 0.795 | precision 0.144 | ROC-AUC 0.890 | PR-AUC 0.358

Make the minority class count. class_weight='balanced', the simpler of the standard fixes, tells logistic regression to penalize a missed fraud far more than a missed legit, in proportion to their rarity. SMOTE (Synthetic Minority Over-sampling) instead grows the training set with plausible synthetic fraud examples until the classes are even, and, crucially, it lives inside the imblearn pipeline so it resamples only the training fold, never the test data. Both lift recall from about 0.15 to about 0.80, so the model now catches four of five frauds. Notice that accuracy fell to about 0.80. That is fine, because we happily trade meaningless accuracy for real fraud caught.

STEP 9 · THE RIGHT CURVES
ROC and precision-recall
Two threshold-free views of ranking quality.

ax[1].axhline(y_test.mean(), color=GREY, ls='--', label=f'baseline {y_test.mean():.3f}')

plt.tight_layout(); plt.show()

Prefer the PR curve for rare events. The ROC curve looks great (AUC 0.89), and the model does rank fraud above legit far better than chance. But ROC can be over-optimistic under heavy imbalance, because a huge legit class makes the false-positive rate look tiny. The precision-recall curve is the honest view. Its baseline is the fraud rate itself (about 0.04), and our PR-AUC of 0.36 is many times that, which is real signal. It also shows the hard truth that pushing recall up costs precision. This curve is what you negotiate the operating point on.

STEP 10 · TUNE THE THRESHOLD TO COST
0.5 is the wrong cutoff for fraud
Let the cost of each error choose the line.
In [11]:
# Choose the threshold on out-of-fold predictions for the TRAINING rows, so the test set stays untouched.
from sklearn.model_selection import cross_val_predict
COST_FALSE_ALARM = 5      # analyst review / customer friction, in dollars
plain_pipe = Pipeline([('prep', preprocess), ('clf', LogisticRegression(max_iter=3000))])
oof = cross_val_predict(plain_pipe, X_train, y_train, cv=5, method='predict_proba')[:,1]
amt_tr = X_train['amount'].values; y_tr = y_train.values
def total_cost(p, y_true, amounts, t):
    pred = (p >= t).astype(int)
    missed = (pred==0) & (y_true==1); false_alarms = ((pred==1) & (y_true==0)).sum()
    return amounts[missed].sum() + false_alarms*COST_FALSE_ALARM   # missed fraud costs the transaction amount
ths = np.linspace(0.02, 0.60, 59)
cost = [total_cost(oof, y_tr, amt_tr, t) for t in ths]
best_t = ths[int(np.argmin(cost))]
fig, ax = plt.subplots(figsize=(7.8,4.2))
ax.plot(ths, cost, color=EM, lw=2.4); ax.axvline(0.5, color=GREY, ls='--', label='default 0.50')
ax.axvline(best_t, color=RED, ls='--', label=f'cost-optimal {best_t:.2f}'); ax.set(xlabel='decision threshold', ylabel='total cost on training folds ($)', title='The cost-optimal threshold is far below 0.5'); ax.legend()
plt.tight_layout(); plt.show()
amt = X_test['amount'].values; yv = y_test.values
for t in [0.50, best_t]:
    pred=(prob>=t).astype(int)
    print(f'test set at threshold {t:.2f}: recall {recall_score(yv,pred):.2f} | precision {precision_score(yv,pred):.2f} | flags {pred.mean():.1%} of transactions')

test set at threshold 0.50: recall 0.15 | precision 0.68 | flags 0.8% of transactions
test set at threshold 0.05: recall 0.74 | precision 0.16 | flags 18.0% of transactions

Move the line to where the money is. A fraud model outputs a probability; the threshold turns it into an alert. Because a missed fraud costs the whole transaction while a false alarm costs a few dollars, the expected-cost curve bottoms out far below 0.5, at 0.05. The cell picks that cutoff on out-of-fold predictions for the training rows, so the test set stays out of the choice. On the test set, lowering the cutoff from 0.50 to 0.05 lifts recall from 0.15 to 0.74, catching about five times as much fraud and flagging 18% of transactions, at the price of more false alarms the review team can absorb. This threshold is the real business dial, and it matters more than the choice of model.

The model is legible. The drivers line up with intuition. Foreign and card-not-present transactions, high velocity (many transactions per hour), electronics/travel merchants, and large amounts raise risk, while long-established accounts and everyday merchants lower it. These are the patterns built into this teaching dataset, and the model recovered them, which is the check a readable model makes possible and a reason to keep a simple logistic model.

STEP 12 · DEPLOY ON NEW DATA
From notebook to a live decision
Persist the pipeline, then score transactions it has never seen.
In [13]:
import joblib
DECISION_THRESHOLD = best_t   # the cost-tuned cutoff from Step 10
deploy = plain_pipe.fit(X_train, y_train)          # the plain model, whose probabilities the threshold was tuned on
joblib.dump(deploy, 'fraud_model.joblib')          # the WHOLE pipeline: preprocessing + model in one file
model = joblib.load('fraud_model.joblib')        # what production would load
# two transactions the model has never seen, arriving live:
new_txns = pd.DataFrame([
  {'amount':1450,'hour':3,'txns_last_hour':6,'foreign_transaction':1,'card_present':0,'account_age_days':40,'distance_from_home_km':900,'merchant_category':'electronics'},
  {'amount':38,'hour':13,'txns_last_hour':1,'foreign_transaction':0,'card_present':1,'account_age_days':1500,'distance_from_home_km':6,'merchant_category':'grocery'}])
scores = model.predict_proba(new_txns)[:,1]
for i, p in enumerate(scores):
    decision = 'HOLD for review' if p >= DECISION_THRESHOLD else 'approve'
    print(f'transaction {i+1}: fraud probability {p:.2f}  ->  {decision}')
print('\nno manual preprocessing needed: the saved pipeline applies the exact same transforms as training.')

transaction 1: fraud probability 1.00  ->  HOLD for review
transaction 2: fraud probability 0.00  ->  approve

no manual preprocessing needed: the saved pipeline applies the exact same transforms as training.

Deployment is where the ongoing work begins. Saving the fitted Pipeline with joblib bundles the preprocessing and the model into one object, so production applies the identical transformations as training, which rules out train/serve skew. Scoring a brand-new transaction is then a single call. The large, late-night, foreign, card-not-present electronics purchase on a 40-day-old account far from home is held for review, and the small daytime grocery run on an established local account is approved, both decided in milliseconds by comparing the score to the cost-tuned threshold. Fraud patterns drift, so production needs drift monitoring, a feedback loop that feeds confirmed frauds back into retraining, and analysts on the borderline alerts. Operationalizing exactly this is the subject of Chapter 130.

Fraud detection in one view¶

  1. Accuracy is a trap on rare-event data, since a do-nothing model was 96% accurate and caught zero fraud.
  2. Judge fraud models by precision, recall, and PR-AUC, and stratify the split so both sets keep the fraud rate.
  3. Rebalance the learning with class_weight='balanced' or SMOTE (inside an imblearn pipeline) to lift recall from about 0.15 to about 0.80.
  4. The precision-recall curve is the honest ranking view for rare events; ROC can flatter.
  5. Tune the threshold to cost: a missed fraud dwarfs a false alarm, so the optimal cutoff sits far below 0.5.

On rare-event problems, the metric and the threshold matter more than the algorithm.
